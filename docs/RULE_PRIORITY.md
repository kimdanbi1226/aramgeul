# 아람글 규칙 우선순위 정책 (초안)

> 작성 기준: 2026-10-01
>
> 목적: 여러 출처가 동시에 관여할 때 아람글이 임의로 판단하지 않고, 무엇을 판정하는가에 따라 근거와 처리 순서를 일관되게 적용하기 위한 내부 정책이다.

## 1. 핵심 원칙

아람글은 모든 출처를 하나의 정답 데이터로 합치지 않는다.

각 출처는 다음처럼 역할을 분리한다.

- 규범: 무엇이 규범에 맞는가?
- 교정 엔진: 입력 문장에서 어떤 오류 후보를 찾고 어떻게 교정하는가?
- 사전: 어떤 표제어·품사·의미·용례 정보가 있는가?
- 전문 용어: 특정 분야에서 어떤 용어가 사용되는가?
- 설명: 사용자가 왜 그렇게 고치는지 이해하도록 어떻게 설명하는가?

따라서 사전에 있음과 맞춤법상 맞음은 동일한 상태가 아니다.

## 2. 판단 유형

아람글의 결과는 최소한 다음 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| ERROR | 규범 또는 검사 기준에 따라 오류로 판단할 수 있음 |
| CORRECTION | 교정 후보와 교정 결과를 제시할 수 있음 |
| VALID | 현재 확인된 기준에서 오류 근거가 확인되지 않음 |
| DICTIONARY_ONLY | 사전 등재 정보는 확인되지만 그 자체로 규범 판정을 의미하지 않음 |
| TERM_ONLY | 전문 용어 정보가 확인되지만 일반 맞춤법 판정과는 별개 |
| REGISTER | 표현 자체보다 문체·격식·문서 유형에 따른 권장 여부 |
| AMBIGUOUS | 문맥이 부족하여 하나의 결과로 확정하기 어려움 |
| NO_DECISION | 현재 연결된 자료만으로 신뢰할 수 있는 판정을 만들 수 없음 |

VALID는 모든 상황에서 절대적으로 옳다는 뜻이 아니라, 현재 검사 범위에서 오류를 확인하지 못했다는 의미로 사용한다.

## 3. 출처의 역할별 우선순위

### 3.1 맞춤법·띄어쓰기·규범 위반 판정

기본 흐름:

1. 국립국어원 어문 규범 및 아람글에 명시적으로 구현한 규칙
2. Bareun의 교정 후보 및 관련 설명
3. 사전/용어 데이터의 어휘·의미·용례 정보
4. AI의 문맥 설명

중요:
- AI가 규범 판정을 새로 만들어서는 안 된다.
- 사전 등재 여부만으로 오류를 확정하지 않는다.
- Bareun이 제안한 교정이라도 규범 근거와 충돌하거나 문맥상 불확실하면 즉시 확정하지 않고 검토 상태로 둔다.

### 3.2 어휘·의미·품사 정보

기본적으로:

1. 표준국어대사전
2. 우리말샘
3. 한국어기초사전
4. 온용어(전문 용어 문맥)

단, 이 순서는 우열 순위가 아니라 질의 목적에 따른 기본 조회 순서다.

예:
- 표준어·표제어 확인 → 표준국어대사전 우선
- 신어·생활어·폭넓은 어휘 확인 → 우리말샘 적극 활용
- 학습자용 의미·예문 → 한국어기초사전 활용
- 특정 분야의 전문 용어 → 온용어 우선

## 4. 충돌 처리

### A. Bareun과 규범 기준이 일치

→ 교정 결과를 ERROR 또는 CORRECTION으로 처리할 수 있다.

### B. Bareun은 교정을 제안하지만 규범 근거가 불명확

→ 자동 확정하지 않는다.
→ AMBIGUOUS 또는 별도 검토 후보로 보낸다.

### C. 사전에 등재되어 있지만 Bareun/규범상 오류 후보

→ 사전 등재 사실을 이유로 오류를 무효화하지 않는다.
→ 등재되어 있음과 해당 문맥에서 적절함을 별도로 표시한다.

### D. 우리말샘에만 등재

→ 오류로 판정하지 않는다.
→ 등재 사실과 문체/사용 영역 등의 정보를 보조 정보로 활용한다.

### E. 온용어에 등재

→ 전문 용어 후보로 활용한다.
→ 일반 맞춤법 오류를 자동으로 무효화하지 않는다.
→ 해당 결과의 공공누리 이용 조건을 함께 기록한다.

### F. 출처끼리 서로 다른 교정 후보 제시

→ 자동으로 한 후보를 정답으로 고르지 않는다.
→ 문맥과 규범 근거를 추가 확인한다.
→ 필요한 경우 AMBIGUOUS로 반환한다.

## 5. 문체·격식 판단은 별도 계층

예를 들어 알바와 아르바이트, 컨펌과 확인처럼 표현 자체가 무조건 틀린 것이 아니라 문서 목적에 따라 권장 표현이 달라지는 경우가 있다.

따라서:

- 일반 모드: 표현의 오류 여부와 사용 가능성을 중심으로 판단
- 자기소개서·이력서: 공식적이고 일관된 문체를 우선하는 추천을 별도 표시
- 논문·학술문: 학술적 문체와 전문 용어 사용을 별도 표시

이 경우 ERROR와 REGISTER를 혼동하지 않는다.

## 6. AI의 역할 제한

AI는 다음을 수행할 수 있다.

- 검사 결과를 자연스러운 한국어로 설명
- 규범/사전 조회 결과를 사용자의 문맥에 맞게 설명
- 두 표현의 차이를 정리
- 문서 유형에 맞는 표현 선택지를 설명

AI는 다음을 단독으로 수행하지 않는다.

- 국립국어원 규범에 없는 규칙 생성
- 사전에 없는 표현을 근거 없이 오류 판정
- Bareun 결과를 근거 없이 뒤집기
- 출처가 없는 사실을 국립국어원이 정한 규칙처럼 표현
- 문맥이 부족한 상태에서 하나의 표현만 절대적 정답으로 확정

## 7. 결과 데이터에 저장할 근거

각 판정에는 가능하면 다음 정보를 남긴다.

source
source_type
source_url
source_version
rule_id
decision
confidence
checked_at

예시 데이터:

{
  "source": "National Institute of Korean Language",
  "source_type": "norm",
  "source_url": "...",
  "source_version": "...",
  "rule_id": "spacing-001",
  "decision": "ERROR",
  "confidence": "high",
  "checked_at": "2026-10-01"
}

실제 서비스에서는 사용자에게 필요한 정보만 보여주고 내부적으로는 근거를 추적할 수 있도록 한다.

## 8. 자동 확정 금지 조건

다음 중 하나라도 해당하면 자동으로 확정하지 않는다.

- 문맥에 따라 의미가 달라질 수 있음
- 둘 이상의 교정 후보가 존재함
- 사전 등재 여부와 규범 판단이 충돌함
- 전문 용어 여부가 문서 맥락에 영향을 줌
- API 응답이 불완전하거나 오류 상태임
- 출처의 버전이 확인되지 않음
- AI의 추론만으로 판단해야 하는 상황

이 경우 사용자에게 틀렸다고 단정하기보다 필요한 문맥 또는 근거를 제시한다.

## 9. 구현 순서

이 정책을 코드에 바로 하드코딩하지 않는다.

다음 단계에서:

1. 규칙 ID 체계 정의
2. 규칙 메타데이터 구조 정의
3. Golden Test Set 작성
4. 대표적인 충돌 사례를 테스트 케이스로 등록
5. 그 후 검사 엔진에 정책을 구현한다.

## 10. 정책 변경 원칙

출처 API의 정책이나 데이터 구조가 변경되면 코드만 수정하지 않는다.

다음 정보를 함께 갱신한다.

- 정책 문서
- 출처 버전
- API 응답 스키마
- 관련 규칙
- Golden Test Set
- 변경 이력

이를 통해 나중에 같은 문장이 왜 다른 결과를 받았는지 추적할 수 있도록 한다.
